What the numbers mean

Task attemptOne benchmark problem, tried once by one setup. Example: "Gemini Carbon + Jev handles one airline customer request."
LLM aloneGemini gets the whole tool list and decides by itself which tool to use.
+ Jev / + SubQ Snap / + Gemini DecisionA fast "decision model" reads the request first and picks the 3–8 most likely tools (with a "give me more tools" escape hatch). Gemini then only sees those. Everything else stays the same.
Small / large tool listSmall = only the tools that belong to the problem (13–32). Large = padded with tools from other apps (~55–100), the way a real assistant connected to many services looks.
CorrectThe benchmark's own grader says the job was done right: τ-bench checks the final database and what the customer was told; MCPToolBench++ checks the tool call against the answer key.
Time to first tool callHow long until the AI takes its first action, right or wrong.
Time to first correct tool callHow long until it takes the right action. This is the wait a user actually feels.
Total task timeAll the AI's thinking time for the task (decision model + Gemini). Tool execution and the simulated customer's replies are not counted, so every setup is timed the same way.
Live response time chartsAverage time each provider took to answer one call, minute by minute, stored in Tiger Data.
